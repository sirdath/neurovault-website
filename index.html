How recall works

One sweep. The passages that matter.

Recall doesn't keyword-match and hand you the whole file. A single query fires through the whole synapse web and lights up only what's relevant - then returns the handful of passages, not the haystack.

semantic

sqlite-vec finds what you meant - even when no keyword matches the way you phrased it years ago.

BM25

Keyword precision catches exact names, IDs, and rare terms semantic search glosses over.

graph

The entity knowledge graph pulls in connected notes - the neighbourhood around a hit.

RRF + rerank

All three are fused via RRF and reranked by a cross-encoder, so the best passage rises to the top.

New · Multi-agent coordination

One shared brain. Many agents.

Agents route work to each other and read their own inbox through a single local brain. Each gets its own view; none steps on another.

handoff

An agent routes a task - with full context - straight to another agent's queue. No copy-paste, no lost thread.

agent_inbox

Each agent reads only the work addressed to it - a private queue inside the shared memory.

session_start(agent=X)

Names the agent and scopes its view, so a fleet shares one brain without a shared identity.

A coordination substrate, not an orchestrator - it never runs or schedules agents.

New · Confidence on recall

Every fact carries a trust signal.

Relevance tells the agent a fact matches the query. Confidence tells it whether to rely on it - a separate 0-1 signal, especially for facts written by other agents. Computed structurally. Zero LLM at recall time.

Data safety

100% local. Actually.

Private by architecture, not a setting you switch on.

No telemetry

No analytics, no crash reporter, no phone-home on startup.

No account

There is no NeuroVault login to create or sign into.

No cloud

Your vault is a folder of markdown files. Back it up, sync it, or delete it however you like.

Loopback only

The backend binds to 127.0.0.1:8765 and refuses connections from other machines.

No API keys

NeuroVault never holds one. Embeddings run on-device with BGE-small ONNX.

Network on request

The only outbound call by default: downloading the embedding model on first run.
